Citadel Ops Desktop — functional spec for UI (vs Stitch mocks)
================================================================
Use this when refining Stitch prompts or implementing the redesign.
Source: Client/src (current behavior).

GLOBAL CHROME (Header + Sidebar)
--------------------------------
Header (fixed):
  - Logo + "Citadel Ops" + "Desktop" label
  - Credits (OPS coin), loading state
  - Castle focus badge (popover) — must stay visible
  - APP RAM (Go) + CHROME RAM — real telemetry, not decorative
  - Auto Bird: ON/OFF toggle, optional "Next Bird in Xh Ym" when enabled
  - Bot status: Connected / Reconnecting (n s) / Disconnected
  - Start Bot / Stop Bot (game session)
  - Auto Bird settings (gear) opens modal

Sidebar (fixed, ~256px):
  - Game Functions: Recruit ON/OFF + Recruit settings (gear) → modal
  - Main Menu: Dashboard, Units, Equipment, Decorations, Event Modules, Currency
  - System: Settings, Support
  - Theme toggle

Modals (not full-page routes):
  - AutoBirdSettingsModal, RecruitTroopsSettingsModal
  - InsufficientCreditsModal, Alerts, UpdateModal, LoginCredentialsModal
  - SettingsView also opens PriorityModal for attack tab priorities

Default landing view in code: equipment (not dashboard).


DASHBOARD (route: dashboard)
----------------------------
Purpose: Per-castle economic overview.
Data: CastleResourceContext — one card per castle.
Each castle card shows:
  - Castle name
  - 10 resources with game icons: wood, stone, food, coal, oil, glass, iron,
    honey, mead, beef — each: current / max, progress bar, net /hr (food/mead/beef
    subtract consumption from prod)
  - Sections: Recruitment Queue, Tool Queue — currently PLACEHOLDERS (5 empty slots each)
    → UI should allow "empty/coming soon" or future real queue rows, not fake filled data.

Empty/loading: "Loading castle data..." when no castles.


UNITS (route: units)
--------------------
Purpose: Per-castle troop counts from same castle context.
Data: troopsMixed (total), troopsI (in castle), troopsTU (travelling) per unit ID.
UI: Grid of unit tiles — UnitImage, total count, "(inCastle / travelling)", name from
     TROOP_DEFINITIONS.
Empty: "Loading unit data..." until castles with troop maps exist; per-castle "No units found".

Not in app today: tier columns, heal bars, training queue table, filters — those were
generic game-UI in mocks. Add only if backend exposes them.


EQUIPMENT (route: equipment) — primary workspace
------------------------------------------------
Purpose: Commander vs Castellan loadouts, PvP/PvE, slot grid + stat priority / optimizer.
Layout: Left ~flex: EquipmentSelection (mode toggles, combat mode, slot list/detail).
         Right fixed ~320px: StatPriority (credits + hardwareID + selected slot).
Must preserve: equipmentMode (Commander | Castellan), combatMode (PvP | PvE),
               selected slot index, integration with EquipmentContext.


DECORATIONS (route: decoration)
-----------------------------
Purpose: Castle-scoped decoration presets (game focus in JAA), not a generic asset shop grid.
Depends: castleFocus from Auth (aid); kingdom id for apply.
UI: Focused castle label + CastleFocusHoverPopover + Refresh focus
     New preset name input → Save (websocket: save current pickup-eligible layout)
     List presets: Apply, Delete; show decorationPlacerProgress messages when applying
Empty/disabled: save/apply/delete disabled when no focused castle (castleId <= 0).

Mocks showing "PLACE" tiles / rotation inspector / Gothic presets are wrong metaphor —
replace with: focus + preset list + progress text + save/apply/delete.


EVENT MODULES (route: event-modules)
------------------------------------
Current implementation: placeholder copy only ("coming soon").
Functional spec for design: either keep a minimal "empty state + roadmap" panel OR
define real features before investing in dense event cards. Do not design fake
countdown/reward cards unless product defines events.


CURRENCY (route: currency)
--------------------------
Purpose: Read-only global inventory from ResourceContext, grouped:
  Building: relic_shard, sceat, ducat, const_token, upgr_token, plaster
  Combat: affl_tix, drg_scale, drg_spl, might_pt, glory_pt, gallan_pt
  Speedups: min1, min5, min10, min30, hr1, hr5, hr24
Each cell: formatted name, icon (PNG or SVG), numeric value. No transaction log in app.

Mocks with "Gems/Gold/Silver" and transaction tables are inaccurate — use real group names
and keys above (or neutral "Resource" labels if icons carry meaning).


SETTINGS (route: settings)
--------------------------
Title in UI: "System Settings"
Sections:
  1) Attack Scheduler — min/max random delay between attacks (seconds), min >= 4.0,
     persisted via websocket sendSaveSchedulerSettings; loaded via sendGetSchedulerSettings.
  2) Priority Categorization — button opens PriorityModal (P1/P2/P3/Ignored tabs).

Not in this page: General/Auto Bird/Recruit/Appearance as separate sub-nav — those live in
header/sidebar/modals. A mock with many fake settings sections would mislead implementers.


SUPPORT (route: support)
------------------------
Purpose: CustomMessageSender (raw/diagnostic messages) + Discord CTA (single invite link).
Not in app: FAQ accordion, email gateway, search — optional future only.
