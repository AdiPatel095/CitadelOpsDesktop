# Hosted process memory containment

> **CIT-47:** hosted runtimes (`BackgroundOnly`) no longer create a telemetry store, so there are no frame or feature logs, tails, write buffers or telemetry queues on a hosted cell, and the worker serves no `/api/v2/telemetry/*` routes. The telemetry statements below describe desktop mode. `/orchestrator/v1/diagnostics` still returns the `telemetry` and `telemetryStores` fields, always zero on a hosted cell. Confirmed attack-launch counts on hosted come from a receipt-derived ledger in `Runtime/Operations.sqlite`.

The worker exposes token-protected `GET /orchestrator/v1/diagnostics`. Values are process-wide, including shared catalogs and all account runtimes. Go memory metrics are cached for five seconds; reading them never forces GC. Queue statistics aggregate fixed numeric fields across current active and stopping telemetry stores. Removal/reset can reduce these counters; they are not process-lifetime cumulative values. Post-GC live bytes and completed GC cycles are read in the same runtime/metrics sample; the separate MemStats NumGC/LastGC read can straddle a collection. No account IDs, channel labels, payloads, paths, raw errors, profiles or credentials are returned. Existing account diagnostics remain compatible.

Each telemetry store accepts at most 16 MiB of owned line/channel payload bytes and 8192 records across pending and detached in-flight batches. Entry metadata is bounded by that record limit; the queue backing array and writer batch are bounded separately. Batches contain at most 128 records and normally 1 MiB; one accepted larger record is written alone. Three stores accept at most 48 MiB of queued/in-flight payload, plus bounded metadata and live tails. This is a telemetry bound, not a bound on all process allocations.

Producers never wait for disk. Overflow or oversized optional diagnostic/activity logs are dropped newest without truncation. Accepted records retain FIFO order. Drop counts/bytes, oversized records, write failures, live-tail evictions, flush rejection/cancellation/timeouts and drain latency report loss. Live tails keep the existing line limits and latest-record order, with 8 MiB per diagnostic channel and 1 MiB per feature/activity channel. Oversized tail records are omitted whole; persistence can still accept them within its independent budget. Stored strings own their backing allocation; tail and queue share that owned copy.

Operations.sqlite operation reservations/checkpoints and Reports.sqlite archive transactions remain independent durable paths. Attack timestamp/rate accounting is independent of optional log persistence and is unchanged. Telemetry persistence is best effort: a failed write makes flush fail, data-directory changes are refused, and tail reads use current memory rather than presenting stale disk as current.

Flush uses accepted-sequence frontiers, not queued markers. At most eight callers wait, excess callers fail explicitly. Disk-tail readers are limited to two per store, use bounded nonblocking lock attempts and fall back to current memory on contention. Cancellation/deadlines return without spawning waiter goroutines. Shutdown coalesces onto the existing writer. A blocked filesystem write itself cannot be canceled by Go: bounded callers can time out, but the single writer retains its bounded batch until I/O resumes. Actual teardown also waits for admitted disk-tail readers; closing rejects new disk readers. Supervisor keeps its stopping/profile admission slot until both application and telemetry teardown finish; one cleanup watcher per runtime prevents repeated stop attempts from creating unlimited watchers or bypassing capacity. Process exit remains the final boundary for permanently stalled filesystem I/O.

## Selecting a deployment memory budget

This change sets no production GOMEMLIMIT, GOGC, cgroup limit or admission default. Use representative post-GC live heap, GC CPU/latency, reconnect activity, retention sweeps and catalog-refresh peaks before selecting values. The required predicates are:

- GoBudget + measured non-Go/burst reserve < HardContainerLimit, including tested transient working-set and non-Go allocation headroom.
- HardContainerLimit + measured peak non-worker reserve + host safety reserve < usable host RAM. Reserve includes networking, journald, Docker, proxy and other host services.
- The measured live set and transient working set must fit the chosen Go budget without unacceptable GC slowdown. GOMEMLIMIT is soft and is not a substitute for a hard container boundary.

Cgroup usage includes reclaimable file/slab memory. RSS is not post-GC live heap. The recovered approximately 1.6 GiB RSS observation does not establish a safe budget. Historical OOM records lack a correlated queue/heap series or allocation profile; no feature or telemetry backlog is proven as the incident cause. Deployed source had no profile endpoint, and this change adds none. Maps and catalog refresh remain measurement candidates, not diagnosed leaks.
