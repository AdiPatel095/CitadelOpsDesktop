# 2.4.0 — pending release

This is a queued release item, not a declaration that 2.4.0 is published. Keep
the shipping version and 2.3.6 patch notes unchanged until the actual release.

## Fixed

- Duplicate alliance-help rejections (`AHR 273`, official
  `NO_MULTIPLE_ALLIANCEHELP`) no longer create an automation lane safety lock.
  The rejection remains visible as a failed operation; no new automatic retry
  is introduced. All other unapproved opcode/code pairs remain guarded, and
  every nonzero MSD rejection retains its mandatory 30-minute cooldown.

## Release integration

- Carry the matching tenant-hotfix policy, official error mapping and tests
  into 2.4.0. Do not revert the hotfix during source promotion.
- Add the Fixed item above to the new 2.4.0 entry in
  `Client/src/config/PatchNotes.ts` when preparing the actual release; mirror
  it to the frontend patch notes and retain canonical change-type ordering.
- Existing persisted incidents are not automatically cleared by the update.
  An exact incident still requires an explicit review and clear.
- Tenant-only early deployment remains version 2.3.6 with its own immutable
  source/build/image receipt. Desktop distribution is deferred to 2.4.0.
