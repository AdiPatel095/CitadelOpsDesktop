## Source inventory

Run `node scripts/inventory-localization.mjs` from Client. `source-inventory.json` contains conservative AST candidates with source references and sink categories. It includes branch values and technical strings in rendered expressions, so counts are not translation counts. Exclusions retain location/reason without duplicating technical text. Missing source candidates, dynamic string composition and false exclusions require semantic review before coverage certification. No fallback English counts as translated.

## Completion gate

`npm run check:localization` intentionally fails while source candidates or dynamic surfaces remain open. Build/test success alone is not translation completion. Catalogs are model-authored and need human linguistic review; official translations retain official provenance even when their text equals English.


Every visible sink needs a reviewed key or a specific exclusion. The strict release gate requires every supported custom catalog to have exactly the English keys and matching recursively parsed ICU argument sets. Unit tests separately validate authored subsets without treating missing entries as complete; missing counts are explicit in the gate. Official game positional placeholders are separate from ICU. Runtime unknown descriptors, unavailable official keys and retained English history must remain visible as coverage gaps. Check all 26 locales, long text, Arabic direction, locale changes during in-flight fetches, offline fallback, account switching, exports and accessibility. Existing physical left/right CSS and all non-header responsive surfaces still need RTL audit.

## Latest implementation checkpoint

Nine whole rich paragraphs use safe ICU tag callbacks; technical code fragments are scalar arguments, and numeric costs use locale formatting. Sixty repeated generated keys were consolidated into twenty reviewed semantic targets; the explicit map is `common-key-map.json`. These are source assignments, not completed translations. The inventory retains 7314 conservative candidates requiring semantic review.

Equipment calculations, deduplication and inferred priorities use canonical English effect metadata independently of selected display text. Same-version locale transitions retain canonical state; failed canonical loads expose an unavailable status and pause reconfiguration. Two verified Japanese v4357 sign defects have explicit versioned display corrections, preserving raw official source. Tests cover real English, Arabic and Japanese strings, German display alternatives, loading/failure stability, unknown placeholders and numeric/identity separation.

Server and backend catalogs are independently owned and lazily loaded. Their partial authored entries are validated and missing entries remain part of the strict gate; synchronization never credits English fallbacks as translated. Browser verification on a disconnected local preview confirmed the explicit unavailable equipment status, disabled actions and Arabic viewer selection; it does not establish connected runtime or full RTL acceptance.
